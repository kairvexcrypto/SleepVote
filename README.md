# SleepVote

Голосование за пропуск ночи для Paper 1.21.11 / Java 21. Проект Warndev.

У каждого настроенного обычного мира свой процент участников, минимальное число игроков и длительность удержания кворума. Учитываются спящие игроки и, если разрешено настройкой, голоса `/svote vote`. Один игрок не получает два голоса за кровать и команду.

Версия 0.1.0 собрана; 34 автоматических теста пройдены. Запуск на игровом сервере ещё не проверен. См. [VERIFICATION.md](VERIFICATION.md) и [ACCEPTANCE.md](ACCEPTANCE.md).

## Установка

1. Выполните `mvn clean verify` на JDK 21 / Maven 3.9+.
2. Установите `target/SleepVote-0.1.0.jar` на тестовый Paper 1.21.11.
3. В `plugins/SleepVote/config.yml` укажите точные имена миров. По умолчанию настроен только `world`.
4. Выполните `/svote reload`, затем `/svote worlds` из консоли или с правом администратора.

Плагин управляет правилом `minecraft:players_sleeping_percentage` в указанных мирах: ставит 101, чтобы обычный механизм пропуска ночи не конкурировал с голосованием. Исходное значение сохраняется до изменения и восстанавливается при штатном отключении. Подробнее — в разделе восстановления ниже.

## Команды и разрешения

| Команда | Действие | Право |
|---|---|---|
| `/svote vote` | Отдать виртуальный голос в текущем мире | `sleepvote.vote` |
| `/svote revoke` | Отозвать виртуальный голос | `sleepvote.vote` |
| `/svote status` | Состояние голосования в текущем мире | `sleepvote.status` |
| `/svote status <мир>` | Состояние другого загруженного мира | `sleepvote.status` и `sleepvote.admin` |
| `/svote worlds` | Настроенные миры и состояние управления | `sleepvote.admin` |
| `/svote leases [страница]` | UUID миров, исходное и текущее правило сна | `sleepvote.admin` |
| `/svote reload` | Прочитать конфигурацию и сбросить текущие голоса | `sleepvote.admin` |

Голосование и свой status доступны игрокам по умолчанию. Административное право — операторам. `sleepvote.exclude` по умолчанию не выдаётся: с этим правом игрок не входит в число участников и его сон не учитывается.

В голосовании участвуют живые игроки Survival и Adventure, если сервер не пометил их `sleepingIgnored` и у них нет права исключения. Creative, Spectator и мёртвые игроки исключены. Автоматического определения AFK или интеграции с vanish нет: используйте соответствующее право в своей системе.

Отзыв голоса не отменяет факт сна в кровати. Для отмены такого голоса игрок должен встать. Выход, переход в другой мир и потеря права участия удаляют виртуальный голос.

## Настройки мира

```yaml
worlds:
  world:
    percentage: 50
    minimum-players: 2
    minimum-votes: 1
    quorum-seconds: 5
    virtual-votes: true
    clear-weather: true
    show-bossbar: true
    night-start: 12542
    night-end: 23459
    morning-time: 0
```

Количество необходимых голосов: `max(minimum-votes, ceil(eligible * percentage / 100))`. При трёх участниках и 50% нужны два голоса. `minimum-players` задаёт минимальное число участников для запуска отсчёта. Если требуемых голосов больше, чем игроков, ночь не пропускается.

Кворум должен сохраняться `quorum-seconds` секунд по монотонным часам. Проверка выполняется раз в 20 тиков; при лаге реакция задерживается до следующей проверки. При потере кворума отсчёт начинается заново. В пределах одной наблюдаемой ночи успешное решение выдаётся один раз.

Границы night-start и night-end включительные, должны лежать в ночном диапазоне 12000..23999. Утро допускается в диапазоне 0..11999. После пропуска при clear-weather сбрасываются дождь и гроза. Виртуальное голосование само по себе не меняет статистику сна, точку возрождения или таймер фантомов.

Поддерживаются только миры Environment.NORMAL. Nether и End не управляются. Сообщения — обычный текст; формат прогресса поддерживает `{votes}`, `{required}`, `{eligible}`. Максимум 64 настроенных мира, файл настроек до 64 КиБ.

## Состояние и восстановление

Голоса и счётчик пропущенных ночей существуют только до перезапуска. Для каждой ночи используется день из fullTime мира. Наблюдаемый переход в день очищает голоса. Команды изменения времени сторонних плагинов могут начать новую ночь и новый раунд голосования.

Файл `plugins/SleepVote/leases.dat` хранит исходные правила сна по UUID миров, до 128 записей, с проверкой контрольной суммы. Запись атомарная; исходное значение сохраняется перед установкой 101. Эта небольшая запись выполняется на основном потоке при включении, reload и загрузке/выгрузке мира; в регулярном цикле голосования файлового ввода-вывода нет.

После аварийного завершения сохранённое исходное значение используется повторно, если правило мира осталось 101. Если администратор изменил правило во время работы, голосование перестаёт управлять этим миром. При отключении плагин не перезапишет стороннее значение. Следующий явный reload снова приобретает управление, сохраняя текущее значение как новое исходное.

При штатном отключении исходные значения возвращаются. Записи для не загруженных миров сохраняются до их загрузки. Не удаляйте leases.dat, пока остаются невосстановленные миры. `/svote leases` показывает необходимые для диагностики значения.

Если leases.dat повреждён, плагин отключается и не угадывает исходные настройки. Сохраните копию файла, восстановите его из резервной копии или вручную восстановите правильные значения gamerule в каждом затронутом мире. Только после осознанного восстановления можно архивировать повреждённый файл и запустить плагин заново.

Если новый config.yml некорректен, действующие правила сохраняются. Если конфигурация корректна, но отдельный мир не позволяет изменить gamerule или запись на диск не удалась, остальные миры могут продолжать работу, а этот мир отмечается как неуправляемый. Это не атомарная перезагрузка всех миров сразу.

Если изменение времени не применилось, голосование в мире приостанавливается до reload, а плагин пытается восстановить правило сна. Проверьте конфликты с другими плагинами времени и сна. Ручное управление временем и gamerule не следует выполнять одновременно с голосованием без проверки результата.

Файловая система должна поддерживать атомарное перемещение. FileChannel.force используется для файла; отдельной синхронизации каталога нет, поэтому поведение при потере питания зависит также от файловой системы. Контрольная сумма обнаруживает повреждение, но не защищает от намеренной перезаписи администратором.

Folia и другие версии Paper не проверены.
